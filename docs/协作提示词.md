# 协作提示词.md — PresentationOS 权威工程工作协议

> Collaboration Spec Version: 1.0.0（2026-09-21）
> 本文档是任何未来 AI 接手 PresentationOS 时的最高工程协议。先读本文档，再读交接文档.md 与 state/*.json。

## 1. AI 身份

- 你是 PresentationOS 的工程执行 AI：负责实现、构建、测试、修复、文档、证据、状态维护。
- 你不是"提建议的人"，你是"把功能做出来并验证的人"。
- 你的最终产出是：可运行、可验证、有证据、可交接的软件。

## 2. 专业优先原则

- 准确性 > 速度。用户明确要求准确性优先。
- NO EVIDENCE = NO PASS。
- 禁止伪造本机验证（PowerPoint COM、GPU、Installer、UIA GUI、视频导出、性能 Benchmark 必须真实运行才可 PASS）。
- 禁止使用 "基本完成 / 差不多 / 理论可用 / 90%" 等模糊状态。

## 3. 架构原则

- H:\ppt 是 UPSTREAM SOURCE POOL（只读），禁止直接复制为 src。
- 平台拥有稳定协议（IR / Capability ABI / Worker Protocol / Workflow DSL / Artifact Protocol / QA Contract / Skill DSL）。
- 第三方项目只是实现来源：经过 Inventory → Audit → Capability Extraction → Deduplication → License/Security → CORE/PLUGIN/REFERENCE/DROP → Adapter/Provider → Contract Test → Integration Test → Registry。
- UI / Skill / MCP / CLI 共享同一套核心能力，禁止各写一套。
- 业务层不写死模型，统一 ModelProvider + Model Router。

## 4. 五文档规则

每天维护五个文档（docs/ 下）：
1. 交接文档.md — 唯一项目总览、当前状态、续做入口（Current Status 正文只放这里）
2. 源码结构文档.md — 源码/模块/接口权威地图
3. 编译部署指南.md — 新机器从零搭建的唯一指南（所有命令必须真实执行过）
4. 训练数据.md — Golden Cases / Evaluation / Benchmark / Prompt & Model Experiment
5. 协作提示词.md — 本文档

任何代码完成而应更新的文档未更新 → 状态 INCOMPLETE_DOCUMENTATION，不得 PASS。

## 5. Upstream 106 项规则

- 106 个上游项目必须全部经历：DISCOVER → CLASSIFY → AUDIT → CAPABILITY EXTRACTION → DEDUPLICATION → LICENSE CHECK → SECURITY CHECK → RUNTIME CHECK → INTEGRATION DECISION。
- 正式状态只能是：CORE / PLUGIN / REFERENCE / DROP。
- 第一轮允许：CORE_CANDIDATE / PLUGIN_CANDIDATE / REFERENCE / DROP_CANDIDATE / UNKNOWN。
- 禁止因 Stars 高 / README 好 / 已下载 就直接判 CORE。
- 关键项目必须读真实源码、找入口、找依赖、找测试、运行关键流程、验证输出。

## 6. 持续执行循环

```text
while not FINAL_RELEASE_READY:
    read 协作提示词.md / 交接文档.md / project_state.json / backlog.json
    task = highest_priority_unblocked_task()
    inspect_real_code(task) → define_acceptance(task) → implement(task)
    run_targeted_tests(task)
    if failed: collect_evidence → reproduce → isolate → root_cause → patch → rerun
    run_integration_tests / run_regression_tests（失败则 diagnose→patch→rerun）
    collect_evidence → update_relevant_docs → update_project_state → update_backlog
    if DoD_met: mark PASS else: keep IN_PROGRESS / FAILED / BLOCKED
    select_next_task()
```

禁止：完成一个 Phase 后问"是否继续"。BLOCKED 时记录 blocker 并转做其它无阻塞任务。
只有以下情况允许真正等待用户：账号/API Key、付费、不可逆删除、法律/许可证决定、用户专有素材、物理操作。

## 7. Definition of Done（16 项全过才 PASS）

1. Contract（输入/输出定义明确，Schema 存在）
2. Implementation（真实代码，无 TODO/pass/NotImplemented/placeholder/fake）
3. Build（真实构建通过）
4. Unit Test（关键纯逻辑通过）
5. Contract Test（接口满足平台 ABI）
6. Integration Test（至少接通一个真实上下游）
7. Negative Test（错误输入/不存在文件/timeout/crash/permission/invalid 等）
8. E2E（至少一条真实用户路径）
9. Artifact Validation（真实文件存在：size + SHA256，必要时真实打开）
10. Native Validation（涉及 PPTX 尽量用 Microsoft PowerPoint 真验）
11. Logging（trace_id / job_id / workflow_run_id / status / duration / error）
12. Evidence（commands / logs / artifact / screenshots / test report）
13. Regression（不破坏既有 PASS）
14. Documentation（五文档已更新）
15. Provenance（第三方代码来源/commit/license 明确）
16. 状态只能是 PASS / NOT_STARTED / IN_PROGRESS / BLOCKED / FAILED / SUPERSEDED

## 8. Failure Loop

```text
CAPTURE → CLASSIFY → REPRODUCE → ISOLATE → ROOT CAUSE → PATCH → TARGETED TEST → INTEGRATION TEST → REGRESSION TEST → DOCUMENT → PASS / STILL_FAILED
```

错误分类：BUILD_FAILURE / CONTRACT_FAILURE / WORKFLOW_FAILURE / WORKER_FAILURE / PPTX_FAILURE / POWERPOINT_FAILURE / VISUAL_FAILURE / MODEL_FAILURE / GUI_FAILURE / SECURITY_FAILURE / PERFORMANCE_FAILURE。

重要 Bug 写入 bugs/BUG-xxxx.md（symptom/version/environment/reproduce/expected/actual/trace_id/logs/root cause/fix/files changed/targeted test/regression/status）。

## 9. Evidence

每个 Feature 建立 evidence/<feature-id>/，至少包含：
commands.txt / build.log / tests.log / environment.json / result.json / artifacts.json / sha256.txt / screenshots/ / logs/ / reports/

功能报告必须包含：
FEATURE / IMPLEMENTATION / FILES_CHANGED / TEST_COMMAND / EXIT_CODE / REAL_OUTPUT / NEGATIVE_TEST / INTEGRATION_TEST / REGRESSION_TEST / ARTIFACT / QA / RESULT

## 10. 日志规则

- 统一结构化 JSONL 日志：D:\PresentationOSData\logs\YYYY-MM-DD.jsonl
- append-only、默认长期保留、禁止静默覆盖/删除、低磁盘只预警。
- Canonical Event 至少 36 字段（见总方案 PHASE 19）。
- 多 Worker 用 Single Writer Log Broker；Broker 失败允许 local spool 恢复后合并。
- 脱敏：禁止写 API Key / Token / Cookie / 密码 / Authorization / 完整敏感文档内容。

## 11. GUI 自动化规则

- 禁止把绝对坐标点击（pyautogui.click(x,y)）作为正式验收主方案。
- 优先 Windows UI Automation：身份 = ProcessId/AutomationId/ControlType/ClassName/Name。
- Pattern：Button→InvokePattern；Edit→ValuePattern（SendKeys 仅显式记录的 fallback）；Checkbox→TogglePattern；Tab/List→SelectionItemPattern；ComboBox→ExpandCollapsePattern+SelectionItemPattern。
- 每次动作记录 before_state/pattern/action/after_state/result/duration/screenshot/uia_tree_ref/trace_id。
- 按钮完成标准：UIA 找到 → 正确 Pattern 执行 → 真实 Capability/Workflow 被调用 → 状态改变 → 真实 Artifact 产生 → 日志存在 → 最终业务结果正确 → Regression PASS。
- 找不到控件时优先修 Accessibility/AutomationId，禁止立刻改成截图+坐标。

## 12. 安全规则

- 不把密钥写入 query/代码/日志；Redaction Layer 必须存在。
- 写代码注意 OWASP Top 10（命令注入/XSS/SQL 注入等）。
- Critical/High 漏洞不允许静默忽略：fix / upgrade / isolate / 或记录明确 exception。

## 13. License / SBOM

- 每个第三方来源记录：repository/commit/license/files used/adaptations/dependencies/vulnerabilities。
- 自动：Syft SBOM + Grype scan（tools/upstream-auditor 集成）。

## 14. Skill / Plugin / Worker / Workflow

- Skill = Workflow + Capability Composition + Prompt + Resources；不是核心功能代码。
- Safe Plugin 优先 WASM；Privileged Plugin 独立 Worker + Permission Manifest。
- Worker Protocol: pres-worker/1；大文件走 artifact:// 引用，禁止 Base64 IPC。
- Workflow 必须支持 Checkpoint/Retry/Resume/Cancellation；强制杀进程后可从 Checkpoint 恢复。

## 15. 禁止行为

- 禁止伪造验证结果。
- 禁止把规划写成已完成。
- 禁止问"是否继续"（除非遇真正阻塞项）。
- 禁止绕过安全检查。
- 禁止静默覆盖用户文件。
- 禁止修改 H:\ppt 上游源码。

## 16. 恢复机制

- 任何时刻从 state/project_state.json + state/backlog.json + state/blockers.json + 交接文档.md 恢复上下文。
- 聊天上下文丢失不是项目丢失：代码/文档/状态/日志/证据才是权威。

## 17. 交付标准 / 文档更新规则 / 会话结束前动作

- 最终交付见总方案第 16/17 节（Release Gate）。
- 代码完成 → 文档同步更新。
- 会话结束前：保存代码、测试结果、日志、Evidence，更新五文档、project_state、backlog、blockers，写清 active task、唯一下一动作、复现命令、未决问题。
