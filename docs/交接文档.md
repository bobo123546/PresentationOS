## 【人类快速了解】

- **项目一句话**：PresentationOS 是一个从零建设的 AI Presentation Development Platform —— 专业 AI PPT 桌面软件 + 演示引擎 + 可扩展 Capability/Worker/Skill/Plugin 平台。
- **解决什么问题**：把"用 AI 做 PPT"从散乱的 106 个 GitHub 项目拼盘，变成一个统一、可维护、可验证、可长期升级的软件产品（一个 EXE，而不是 106 个仓库）。
- **适合谁**：需要专业 PPT 的终端用户；需要可替换模型/引擎/能力的开发者；需要把 PPT 能力接入 Agent（MCP/Skill/CLI）的团队。
- **当前实际能做什么**：核心 Vertical Slice 已打通 —— Markdown → DeckSpec → Layout → PptxGenJS → 可编辑 PPTX → PowerPoint Native QA（4 页，PDF 导出，COM 真验 PASS）。已有：Schema/IR v1 + 校验器（7/7）、Capability ABI/Registry/Graph（8/8）、Worker Protocol + Node Worker E2E（4/4）、Artifact Store（5/5）、Durable Workflow SQLite（5/5）、统一日志 telemetry（5/5）、PPTX Engine（4/4）、106/106 upstream manifests + SBOM + Grype 扫描。

- **最短运行步骤**：`cd D:\PresentationOS` → `node tools/vertical-slice/markdown-to-deck.mjs tools/vertical-slice/sample.md "D:\PresentationOSData\projects\vs-demo\deck.pptx"` → `powershell -ExecutionPolicy Bypass -File tools\vertical-slice\qa-powerpoint.ps1 -Pptx ...\deck.pptx -OutDir ...\qa`（PowerPoint COM 打开并导出 PDF 验证）。

## 正文

### 1. 项目背景与起源
用户长期调研 AI PPT 生态（三波：PPT skill 安装 → 全库调研手册 → 106 项批量下载到 H:\ppt），最终决定不"拼 106 个仓库"，而是从零建设统一平台 PresentationOS，把上游项目当作实现来源逐步吸收。

### 2. 业务目标
交付一个正式可用的 AI PPT 桌面软件 + 可扩展演示引擎平台，支持 Markdown/PDF/DOCX/PPTX 输入 → AI 叙事 → 布局 → 可编辑 PPTX → 多层 QA → PowerPoint 真验 → 导出 PPTX/PDF/PNG，后期支持 Speaker Notes/TTS/MP4。

### 3. 目标用户
终端用户（做 PPT 的人）；开发者/团队（Skill/Plugin/MCP/CLI 集成）。

### 4. 核心问题
106 个项目各自为政、不可直接合并；需要稳定协议层 + 可替换执行层 + 可验证质量层。

### 5. 使用场景
商务汇报 / 学术课程 / 数据咨询 / 营销方案 / 模板复刻 / 截图重建 / 自动化批量生成。

### 6. 非目标
不做 106 个项目 UI 拼盘；不做仅"Prompt→PPTX"演示程序；不承诺在核心链路稳定前做 100 个 Style。

### 7. 最终交付定义
总方案第 16 节清单：完整源码、PresentationOS.exe、Installer、CLI、MCP、PowerPointWorker.exe、全部 Worker、各 IR Spec、Capability ABI/Graph、Worker/Workflow/Artifact/Skill/Plugin Spec、106 Audit+manifests、SBOM/License/Security、Mechanical/Visual/PowerPoint QA、Golden/Regression/Recovery/GUI 套件、示例 Skill/Plugin/Workflow、五文档、统一日志、Evidence、Bug History、Release Manifest+Checksums。

### 21. 踩坑清单
- github 直连超时 → 必须走系统代理 127.0.0.1:7897（每个 git 命令前设置）。
- 系统 python 3.14/3.13 混杂 → Python Worker 用 uv 独立 3.11/3.12 环境隔离。
- rustup/dotnet 安装脚本需代理下载。
- H 盘 exFAT：无 ACL/日志特性，不适合放代码仓库。
- Rust MSVC link.exe 缺失 → GNU 工具链 + LLVM MinGW linker（勿再试 msvc）。
- PptxGenJS 无 'column' 图表类型 → 映射 'bar'（BUG-0001）。
- Layout Engine 负尺寸 → PowerPoint 报 0x80070570 损坏（BUG-0002，已 clamp）。
- PS 5.1 `//` 不是注释（脚本头注释必须 `#`）；Out-File -Encoding utf8 写 BOM，读 JSON 需 strip。
- sbom-batch.ps1 必须用 `"dir:$($d.FullName)"` 引号写法且 stdout 重定向到文件。
