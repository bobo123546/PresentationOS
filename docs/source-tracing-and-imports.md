# 来源追踪与桌面导入

产品仍为 0.1.2-alpha / NOT_READY。本次实现是确定性的原文编译与来源核对，未接入模型摘要或完整叙事规划。

## 编译合同

Markdown 直接输入和 Markdown 文件导入共用 `markdownSections`。DOCX、XLSX、CSV、TSV、TXT 使用已有正文/缓存单元格解析器，再进入同一分页、修订、渲染和独占发布流程。不支持的对象明确拒绝。

报告包含两个独立 Schema 工件，DeckSpec v1 不增加来源字段：

- `sourceLedger`：输入字节 SHA256、提取文本 SHA256、提取器版本、标题/正文/单元格位置、原文和文本摘要。数量按 source + chunk + UTF-16 范围生成 occurrence ID；相同数值出现在不同主体处是不同记录。`EXTRACTED` 只表示从来源抽取。
- `compiledPageMap`：来源章节、分页片段、实际页码、渲染命令与 OOXML 对象名、原文范围和 fact ID。修订拆页后重新绑定，不沿用旧页号。最终回读绑定同一 PPTX 的 SHA256。

发布门禁核对引用存在、范围及摘要、全部 occurrence、原文顺序和覆盖、表格行列与表头上下文、完整可见对象及实际 PPTX 读回。表头和续页标题允许明确重复；正文片段不能倒序、重叠或遗漏。额外未绑定单元格、删改空格、交换指标归属或添加未授权标题后缀会失败。OOXML 段落表示仅允许 CRLF/CR→LF 行尾规范化，报告明确记录；来源台账仍保留原字符与坐标。

`semanticTruth: NOT_VERIFIED` 与 `paraphrase: NOT_ALLOWED` 是边界，不是待覆盖的成功状态。该流程不能证明源材料真实，也不能证明任意改写保持因果、否定和时间条件。模型叙事、受众偏好、页数预算和语义复核需另行实现。

## 桌面使用

左侧导入文档支持 `.md/.markdown/.txt/.docx/.csv/.tsv/.xlsx`，参考主题支持 `.pptx`。每份源文件最多 16 MiB。模板 ZIP 的单成员解压上限为 8 MiB、总解压上限为 64 MiB；检查声明大小、实际解压上限和 CRC，不能靠压缩后的大小绕过。

文件在解析成功后存入数据目录下 `imports/<kind>/<sha256>.<ext>`，独占创建，同内容去重，不覆盖已有损坏或被替换文件。原始来源文件不会被修改。资产路径受本地数据目录、普通文件和无链接边界限制，所有接口保持同源会话认证。

未改正文时生成直接读取原文件副本，并以同一字节缓冲区再次核对摘要。编辑正文或章节标题会解除原始来源绑定，按当前 Markdown 编译；项目命名、备注和预览布局不解除来源绑定。内容或参考主题改变会使旧输出和 QA 失效。参考 PPTX 只提供主题颜色和字体，不复制母版几何、图片和复杂样式。

桌面编辑器是 Markdown。非 Markdown 文档只有在转换后重新解析仍保持相同正文块和单元格时才允许导入；包含当前编辑器无法无损表示的多行单元格、显著边缘空格等内容会拒绝，原项目保持不变。这类文档可由 CLI 在支持范围内直接编译，不能以编辑器限制推断 CLI 必须丢弃内容。

项目格式 1.1.0 保存 `compileProfile` 中的来源/主题资产与摘要；加载器仍读取 1.0.0，保存时写入 1.1.0，未知版本拒绝。保存及重开均复核来源字节与 Markdown 绑定。大纲每组至多 40 个章节，提供翻组和编号跳转，避免同时渲染数万个按钮。

同名新项目使用不同的项目 ID 和默认保存目录。服务拒绝覆盖不同 ID、非法 JSON 或非项目文件；同 ID 更新在发布前复核旧文件身份和字节哈希。新 JSON 先在同目录暂存、同步和回读，再发布，失败保留恢复文件。首次排他发布需要同卷硬链接支持，不支持时明确失败；尚未实现同 ID 多窗口编辑的完整冲突解决协议。

## 验证与余下门禁

回归包含真实 HTTP 上传、服务器重启、项目重开与编译，以及实际 PPTX 的错误片段/表格/标题反例。事件处理测试不能替代真实 EXE 操作，OOXML 回读不能替代 PowerPoint 打开/保存/重开/全页导出。Native、最终桌面交互、安装与干净机证据分别记录，不从单元测试数量推导。
