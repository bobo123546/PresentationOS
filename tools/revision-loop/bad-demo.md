# AI 内容工厂

## 概述
本页故意塞入超过一千二百字符的超长正文，用于触发密度硬上限（error），从而验证 Revision Loop 的 split 与 reduce_text 修订：修订引擎必须自动把这一页拆成两页或截断超长文本，而不是要求人工修改。Revision Loop 由确定性规则驱动，不依赖任何模型：先对 DeckSpec 做视觉评分（密度、字号层级、对比度、重叠、留白、版式节奏），再根据问题清单逐条应用修订建议，然后重新评分，最多迭代三轮，直到总分达到阈值或无法再改进。这是 PresentationOS 的 QA 闭环的核心，与机械检查（负尺寸、溢出、重叠、未转义 XML、空文本、图表一致性）互为补充。以下是重复填充的内容，用于把本页字符数推高到一千二百以上：AI 内容工厂是一个端到端的演示文稿生成系统，支持从 Markdown 输入直接生成可编辑的 PPTX，并通过 Microsoft PowerPoint 原生打开与导出 PDF 完成最终验证。系统中包含多个相互独立又彼此衔接的模块：Schema 与 IR 定义、能力注册表、Worker 协议、制品存储、持久化工作流、PPTX 引擎、布局引擎、模板 DNA 提取、既有 PPTX 编辑、参考重建、机械质检、视觉质检、修订引擎、插件系统、模型路由、技能运行时与编译器、桌面 GUI 与 UIA 自动化。每一层都有真实的测试与证据，任何功能都要满足完整的完成定义，不允许占位实现，也不允许伪造本机验证结果。这就是本页需要展示的核心内容，目的是让评分器给出明确的密度告警，并让修订引擎能够被真实地验证。
- 要点一：自动评分
- 要点二：规则修订
- 要点三：闭环迭代
- 要点四：渲染验证
- 要点五：原生校验

## 方案一
方案一采用轻量级文本管道：Markdown 解析为 DeckSpec，布局引擎给出每页几何，PPTX 引擎渲染为可编辑幻灯片。该方案优先保证链路最短、依赖最少，适合作为垂直切片的第一条路径。
- 步骤一：准备输入
- 步骤二：解析 Markdown
- 步骤三：构建 DeckSpec
- 步骤四：视觉评分
- 步骤五：应用修订
- 步骤六：重新渲染
- 步骤七：原生 QA

## 方案二
方案二引入参考模板 DNA：从既有 PPTX 中提取配色、字体与标题位置，作为新 Deck 的设计令牌，使生成结果在视觉上继承参考模板。该方案适合企业品牌模板复刻与统一视觉语言的场景。
- 特点：继承视觉
- 特点：统一风格
- 特点：可复用模板
- 特点：可追溯来源

## 方案三
方案三接入模型路由与插件系统：模型路由根据能力选择本地或云端模型，插件系统以受限沙箱或独立 Worker 的形式扩展能力边界。该方案面向完整的产品形态，但依赖外部模型与运行时，因此在本仓库中由本地 mock 与协议层验证先行覆盖。
- 特点：可扩展
- 特点：可插拔
- 特点：可路由
- 特点：可隔离
